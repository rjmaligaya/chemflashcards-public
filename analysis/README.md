# ChemFlashcards — Results analysis scripts (Section 4.2)

Local Python scripts that turn a **participant-data export** into the statistical
results and figures for the thesis Results section. One script per subsection.

> **Just want to run it?** See **[`TUTORIAL.md`](TUTORIAL.md)** — a plain,
> no-coding, double-click walkthrough. This README is the fuller reference.

## The one thing to know about privacy

These scripts **run entirely on your computer**. Each one reads the file path you
give it and writes result tables/plots next to it. Nothing is uploaded, sent, or
shared anywhere — no participant data ever leaves the machine. They use only
standard open-source Python packages (listed in `requirements.txt`).

> The scripts were written **without** any real participant data. They were
> tested against a synthetic dataset generated by `make_sample_data.py` (fake
> people, random numbers). You can regenerate and inspect that demo yourself.

---

## 1. One-time setup

Install the packages the scripts need:

```
cd analysis
pip install -r requirements.txt
```

(`pandas`, `numpy`, `openpyxl`, `scipy`, `statsmodels`, `matplotlib`, plus
`pingouin` and `pyreadstat` for the SPSS-parity features — all standard, all
offline. If `pingouin`/`pyreadstat` are missing the scripts still run; they just
fall back to scipy/statsmodels and write `.csv` instead of `.sav`.)

## 2. Get your data export

From the study admin/export, produce **either**:

- the **`..._all_....xlsx` workbook** (sheets: `Trials`, `Ease ratings`,
  `Predictions`, `Forced choices`), **or**
- a **folder of the per-table CSVs** (`trials*.csv`, `familiarity*.csv`,
  `predictions*.csv`, `forced_choices*.csv`).

Every script accepts either shape with `--data`. Both give identical results.

## 3. Run a subsection

```
python analysis_42i_spacing_effect.py       --data path/to/export.xlsx
python analysis_42ii_acquisition_curves.py  --data path/to/export.xlsx
python analysis_42iii_calibration.py        --data path/to/export.xlsx
python analysis_42vi_baseline_exclusions.py --data path/to/export.xlsx --baseline path/to/questionnaire.csv
```

Add `--out some/folder` to choose where tables/plots go (default: a
`results_4_2/` folder next to your data). Each script also prints a
plain-language summary to the screen.

## What each script produces

### `analysis_42i_spacing_effect.py` — 4.2.i Spacing effect at delay
Spaced-vs-massed **delayed-test accuracy**, collapsed and by format.
- `42i_confirmatory_qblank.csv` — **THE confirmatory primary (H1)**: the paired
  t-test on the Q-blank retention items only, printed first under its own
  banner. The collapsed test below stays as "Version B" (the alternative
  primary) until Dr. Bongers picks.
- `42i_group_comparison.csv` — secondary group-comparison table; the
  *difference* row carries the **paired t-test** statistic, p, 95% CI, Cohen's
  d_z (one row collapsed over format, plus one per format).
- `42i_spss_paired_samples.csv` — SPSS-style Paired Samples Statistics + Test.
- `42i_spss_within_subjects_effects.csv` — the **2×2 repeated-measures ANOVA**
  (schedule × format) as SPSS's Tests of Within-Subjects Effects: F, df, Sig.,
  partial η², plus the sphericity note.
- `42i_data_collapsed.sav` / `42i_data_2x2.sav` — SPSS data files to reproduce
  the paired t and the GLM repeated-measures in SPSS.
- `42i_delayed_rt.csv` — **delayed-test reaction time (H4 behavioural half):**
  per-participant median retrieval latency on the retention items, spaced vs massed
  (correct-only, timeouts excluded), with a paired t-test. This is the "spaced items
  answered faster at the delayed test" contrast — distinct from the practice-phase
  RT in 4.2.ii, which serves H2.
- `42i_scoring_sensitivity.csv` — **delayed accuracy under two scorings:** the
  lenient instrument rule (ignores hyphenation/spacing) and a strict rule re-scored
  from the raw answers (exact IUPAC form required), by schedule × format, so the
  retention estimate can be reported both ways.
- `42i_primary_scoring.csv` / `42i_scoring_flips.csv` — the **primary composite
  rule** (Q-blank lenient, Q-full strict — set by `QFULL_PRIMARY_RULE` in
  `common.py`, ⚑ pending AB sign-off) next to pure-lenient and pure-strict, plus
  per-question-type counts of trials that flip between the two rules.
- `42i_delayed_rt_by_format.csv` — the delayed RT split by question format. The
  Q-full companion filters on *lenient*-correct (a formatting slip doesn't
  invalidate a latency).
- `42i_inverse_efficiency.csv` — median correct RT ÷ proportion correct per
  schedule (retention items; lower = better) — guards against a speed–accuracy
  trade-off masquerading as an RT effect.
- `42i_recency_descriptives.csv` — how many hours before the delayed test each
  cell's items were last practised (descriptive only; explains why the
  schedule × format interaction can't be read as format sensitivity on its own).
- `42i_list_check.csv` — is one practice list (C-1 vs C-2) just easier? Pooled
  accuracy by list plus a mixed ANOVA where a list-difficulty artifact would
  show up as the schedule × counterbalance-option interaction. Expected null.
- `42i_per_participant_advantage.png` — each participant's spaced-minus-massed
  advantage.
- `42i_sample_manifest.csv` — who was included/excluded and why.

Every script also writes a `*_data_*.sav` SPSS file of the dataset behind its
analysis (falling back to `.csv` if `pyreadstat` isn't installed).

### `analysis_42ii_acquisition_curves.py` — 4.2.ii Acquisition & automaticity
Practice curves by schedule across the 4 spaced sessions and 4 massed blocks
(x-axis = *retrieval position*, Session/Block 1–4). The practice-phase RT curve
is **descriptive only** — massed items are re-retrieved seconds apart, so a
massed speed advantage during practice is trivial; the inferential RT test is
at the delayed test (4.2.i / H4).
- `42ii_curves_summary.csv` — first-pass accuracy, trials-to-mastery, and median
  retrieval latency (mean ± SE per session/block). Soft-cap rate included.
- `42ii_per_participant.csv` — the per-participant values behind the curves.
- `42ii_phase_schedule_interaction.csv` — **the H2 crossover test**: a 2×2 RM
  ANOVA of phase (end-of-practice vs delayed) × schedule. The interaction row
  is the "massed looks fine at the end of practice but loses at delay"
  dissociation, tested directly instead of eyeballed.
- `42ii_relearning_spaced.csv` — the within-spaced relearning curve
  (attempts-to-mastery per session position), with the massed values shown only
  as a structural-floor reference, plus soft-cap counts per schedule.
- `42ii_practice_curves.png` — 3-panel figure (one per measure).

### `analysis_42iii_calibration.py` — 4.2.iii Calibration & forced-choice illusion
All per-item calibration metrics are restricted to **first-pass practice
trials** (retries and the delayed test never count).
- `42iii_confidence_calibration.csv` — accuracy at each confidence level (1–4),
  with calibration split into **bias** (scaled confidence minus accuracy;
  overconfident vs under) and **resolution** (Goodman-Kruskal gamma), reported
  separately.
- `42iii_prediction_calibration.csv` — each pre-session prediction vs the
  realized first-pass-correct count (bias, correlation).
- `42iii_forced_choice_vs_advantage.csv` — each forced choice (Set A = spaced,
  Set B = massed) vs the participant's own delayed advantage, with an
  agreement rate (caveated secondary — small-N per-person signs are noisy).
- `42iii_setpref_contingency.csv` — the group-level (Kornell-style) contingency
  of judged-better vs actually-better set at both occasions, plus who changed
  their choice after actually taking the delayed test.
- `42iii_trajectory.csv` / `.png` — EXPLORATORY: confidence and predictions
  across retrieval positions 1–4 by schedule, with per-participant slopes and a
  spaced-vs-massed slope comparison.
- `42iii_timeout_audit_summary.csv` — the timeout taxonomy (empty / correct /
  wrong) and the count of confidence-null timeouts the calibration excludes —
  kept visible because exclusion is the pre-specified primary handling.
- `42iii_holm_family.csv` — every metacognitive p-value this script produces,
  raw and **Holm-corrected** as one pre-specified family.
- `42iii_calibration.png` — 3-panel figure.

### `analysis_timeout_audit.py` — timeout audit (any phase)
The standalone sweep of **every timed-out trial** in an export: what had the
participant actually typed — nothing, a wrong fragment, or (the case that would
matter) a correct answer they never submitted? Scored under both the lenient
instrument rule and the strict exact-form rule; also re-verifies that the
stored `correct` reproduces from `raw_answer` on every trial. Works on
ID-removed exports (rebuilds pseudo-participants from enrollment date +
option, with sanity checks).
- `timeout_audit_rows.csv` — one row per timed-out trial with the typed answer,
  both re-scores, and a case label.
- `timeout_audit_summary.csv` — counts by case / phase / schedule + timeout
  rates.

### `analysis_42vi_baseline_exclusions.py` — 4.2.vi Baseline & exclusions
- `42vi_sample_summary.csv` — the achieved sample counts.
- `42vi_exclusions_manifest.csv` — one row per participant: dev flag, practice
  completion, delayed-test presence, ISI flag, final include/exclude + reason.
- `42vi_prior_knowledge.csv` / `.png` — distribution of the questionnaire
  baseline (only if you pass `--baseline`).
- `42vi_familiarity_summary.csv` / `.png` — baseline familiarity ("Ease
  ratings", 1–7) by set, as secondary characterization.

## The pre-specified decisions baked in (edit in `common.py`)

All study rules live in the **`CONFIG` block at the top of `common.py`** — change
them there, once, and every script follows. As currently set (agreed 2026-07-21):

| Rule | Current setting |
|------|-----------------|
| Counterbalance | `option1` → C-1 spaced / C-2 massed; `option2` → C-2 spaced / C-1 massed |
| "Format" (4.2.i) | `qtype`: Q-blank vs Q-full on the delayed test |
| Dev/test IDs (`dev_mode=1`) | **always excluded** |
| Include only practice completers | **yes** (all 4 spaced + 4 massed blocks) |
| Missing delayed test | **not** an exclusion (completers assumed to have done it) |
| ISI-timing violations (spaced gaps outside 20–28 h) | **flagged, kept** |
| Baseline-ceiling exclusion | off |
| Mastery soft-cap | 5 attempts (`MAX_RETRIES`) |
| Delayed-test primary scoring (`QFULL_PRIMARY_RULE`) | **strict for Q-full items only** (⚑ pending AB sign-off; Q-blank always lenient; flip to `"lenient"` to restore the old primary) |
| Confirmatory primary test (4.2.i) | paired t on **Q-blank retention** accuracy; everything else secondary/exploratory |
| Timeouts in calibration (4.2.iii) | **excluded** (sweep-verified: no timeout has ever been correct) |
| Metacognitive p-values (4.2.iii) | **Holm-corrected** as one family |

To tighten exclusions later (e.g. once N is larger), flip the flags in
`common.py` — `EXCLUDE_MISSING_DELAYED`, add a ceiling, etc.

## SPSS parity — how the Python results line up with SPSS

Your supervisor prefers SPSS; you prefer Python. The scripts are built so the
Python results **are** the SPSS results, and so they can be checked in SPSS.

**You cannot run SPSS's engine from plain Python** (that needs SPSS installed).
What the scripts do instead — via `spss_compat.py` — is four things:

1. **Match SPSS's numbers.** Every inferential test runs through `pingouin`
   (whose output mirrors SPSS) with a `scipy`/`statsmodels` fallback. The core
   statistics (t, df, p, F, 95% CI) are identical across engines. Effect sizes
   are computed the way SPSS defaults do: paired **Cohen's d = d_z** (SD of the
   differences), and **partial eta²** for the ANOVA.
2. **Print the exact SPSS menu path** for each test, e.g.
   *Analyze > General Linear Model > Repeated Measures*.
3. **Write SPSS-shaped tables** — e.g. `42i_spss_paired_samples.csv` (Paired
   Samples Statistics / Paired Samples Test) and
   `42i_spss_within_subjects_effects.csv` (Tests of Within-Subjects Effects with
   partial eta², plus a sphericity note).
4. **Export `.sav` SPSS data files** of the prepared analysis datasets
   (`42i_data_2x2.sav`, `42i_data_collapsed.sav`, etc.). Your supervisor can open
   these directly in SPSS and re-run the test to confirm identical results — the
   `2x2` file is laid out for *Repeated Measures* with two 2-level factors
   (schedule × format).

Which SPSS test each analysis maps to:

| Analysis | SPSS procedure |
|----------|----------------|
| 4.2.i spaced vs massed (collapsed) | Paired-Samples T Test |
| 4.2.i schedule × format | GLM → Repeated Measures |
| 4.2.iii prediction bias vs 0 | One-Sample T Test |
| 4.2.iii predicted vs realized | Correlate → Bivariate (Pearson) |
| 4.2.iii forced choice vs actual | Crosstabs (Chi-square) |

> Note on sphericity: because every within factor in the 2×2 has only two
> levels, Mauchly's test is not applicable (ε = 1) and no Greenhouse-Geisser
> correction is needed — the scripts state this in the output so its absence
> isn't mistaken for an omission.

## The questionnaire baseline (4.2.vi)

Prior knowledge comes from the paper questionnaire (`Questionnaire-2026-06-04`),
which is **not** in the app export. Transcribe it into a CSV (one row per
participant) and pass it with `--baseline`. Two helper files are provided:

- **`baseline_template.csv`** — the exact columns to fill in.
- **`baseline_codebook.md`** — how to code each item.

The **primary** prior-knowledge measure is **Q10** ("provide the IUPAC name of
the chemical shown") scored `q10_named_correct` = 1/0. Because it's binary, its
mean is the proportion of participants who could name the molecule at baseline.
**Q9** (self-rated IUPAC familiarity, 0–4) and the demographics (Q1, Q3, Q4, Q7)
are reported as sample characterization. All column names are configurable in
`common.py` (`BASELINE_*`) if your transcription differs.

## Single-chart figures (`analysis_figures.py`)

Besides the tables (and the two multi-panel compilation figures), the pipeline
writes **one standalone figure per analysis** into
`participant-data/results/figures/` — 18
charts, each with its own title, labelled axes with units, error bars (±1 SE
across participants), and a fixed color convention (spaced = blue, massed =
orange, neutral gray for non-schedule charts; the pair is validated for
color-vision deficiency and survives grayscale printing). Paired
spaced-vs-massed outcomes are drawn as slopegraphs (one thin line per
participant, bold mean), the H2 crossover and schedule × format as interaction
plots, practice measures as position-1–4 curves, and calibration as a labelled
accuracy-by-confidence chart. Runs automatically in `run_all.py`, or alone:

```
python analysis_figures.py --data path\to\export.xlsx
```

## Sharing data or results with an AI assistant — de-identify FIRST

`make_shareable_export.py` produces a copy of an export that is safe to hand to
an AI assistant (or anyone outside the study team):

```
python make_shareable_export.py --data path\to\export.xlsx
python run_all.py path\to\export_SHAREABLE.xlsx
```

It replaces PIDs with random codes (`R01..Rn`, **reshuffled on every run**, so
two shareable exports can't be cross-linked to each other), **date-shifts** every
timestamp so each participant's study starts at a synthetic epoch (2000-01-01 —
inter-session gaps, retention intervals, and recency survive exactly; calendar
dates, time of day, and enrolment order are destroyed), renumbers the database
row IDs, and drops the timezone column. Blanking the PID column alone is NOT
enough — participants were demonstrably reconstructible from the enrolment
timestamps in a PID-stripped export.

It also writes `..._PID_MAPPING_DO_NOT_SHARE.csv` (real PID ↔ code) next to the
output — that file is for the study team only; keep it out of anything an
assistant can read. Run the analysis **on the shareable file** so every table in
`participant-data/results/` inherits the codes; results generated from a raw
export contain real PIDs and should not be shared.

## Where participant data lives — `participant-data/`

Everything that is participant data, or is derived from it, sits under
`analysis/participant-data/`:

| Folder | Holds |
|--------|-------|
| `participant-data/data/` | the raw export `.xlsx` (and the baseline CSV, if transcribed) |
| `participant-data/results/` | every generated table, figure, and `.sav` file |
| `participant-data/rubric-output/` | the Q-full coding sheets — these carry real PIDs and raw answers |

That whole folder is gitignored, so no participant-level file can be committed
by accident. The scripts, guides, item-level slot map, and blank templates in
`analysis/` itself are version-controlled and safe to share. Everything in
`participant-data/results/` is reproducible: re-run `run_all.py` on the export
to rebuild it. **Keep any new participant-derived output inside
`participant-data/`.**
